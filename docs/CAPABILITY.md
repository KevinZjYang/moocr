# Xiaomi-OCR-0 能力测绘报告（M0）

本文件是 moocr 的**功能地基**：所有功能取舍以本报告的实测数据为准，不以模型卡宣传为准。
测试环境：AMD Ryzen 5 5600X / 64 GB DDR4-3066 / **Intel Arc A770 16 GB**（Vulkan 32.0.101.9150）。
运行时：llama.cpp **b12110**（`llama-b12110-bin-win-vulkan-x64`）+ `Xiaomi-OCR-0.Q4_K_M.gguf`(529,297,664 B) + `Xiaomi-OCR-0.mmproj-bf16.gguf`(207,346,624 B)。
全部测试 `temperature=0, seed=42`，显存占用约 4.16 GB。

> 口径声明：官方 fixtures 取自 arXiv 论文页，训练语料可能覆盖，**绝对准确率应视为上界**。
> 因此另建了 nonce（随机汉字 / 随机字母码）与 degraded（模糊/低对比/低分辨率/噪声）两组自造样本做交叉验证。

---

## 1. 速度与成本模型（实测）

### 1.1 解码（生成）速度

| 场景 | 输出 token | 用时 | tok/s |
|---|---|---|---|
| 轻量段落（124 tok） | 124 | 0.77 s | — |
| receipt 整页 | 300 | 3.31 s | 164.5 |
| dense 公式页 | 1613 | 12.03 s | 160.0 |
| 超长上下文（9142 in） | 1603 | 38.13 s | 153.2 |

**结论：decode 稳定在 153–166 tok/s**，随上下文增长轻微衰减（9142 token 上下文时约 −7%）。
Q4_K_M 在 A770 上没有被显存带宽卡住，说明瓶颈在计算侧（18 层线性注意力 + 6 层全注意力）。

### 1.2 预填充（图像编码）成本 —— 超线性，是真正的成本大头

同一张 dense 页（1800×1303）按比例缩放后送入，记录 `timings.prompt_ms`：

| 缩放 | 分辨率 | image tokens | prefill 用时 | 等效吞吐 |
|---|---|---|---|---|
| 0.50× | 900×651 | 630 | 0.34 s | 1846 tok/s |
| 0.75× | 1350×977 | 1372 | 0.82 s | 1667 tok/s |
| 1.00× | 1800×1303 | 2366 | 2.29 s | 1035 tok/s |
| 1.50× | 2700×1954 | 5194 | 8.02 s | 647 tok/s |
| 2.00× | 3600×2606 | 9142 | 27.67 s | 330 tok/s |

token 从 2366 涨到 9142（×3.86），prefill 从 2.29 s 涨到 27.67 s（×12.1）——**幂次约 1.8–2.2，接近平方**。
工程含义：**图像 token 预算是唯一显著的成本旋钮**，而它由输入像素数决定（实测约 **950 token / MP**）。

粗略成本表（可直接写进 UI 的预估器）：

| image tokens | ≈ 像素数 | prefill | 说明 |
|---|---|---|---|
| 600–1400 | <1.5 MP | 0.3–0.9 s | 默认档，普通文档足够 |
| 2400 | 2.5 MP | 2.3 s | 密集文档 / A4 300 dpi 缩到长边 1600 |
| 5200 | 5.5 MP | 8.0 s | 需用户显式开启「高保真」 |
| 9100 | 9.5 MP | 27.7 s | 不推荐，交互上不可接受 |

### 1.3 吞吐（并发）

`--parallel 4`（每槽 8192 ctx）对同一张轻页压测：

| n | 并发 | 总耗时 | p50 延迟 | 吞吐 |
|---|---|---|---|---|
| 8 | 1 | 6.18 s | 0.77 s | 77.7 页/分 |
| 8 | 4 | 4.38 s | 3.11 s | 109.5 页/分 |
| 16 | 4 | 4.99 s | 1.24 s | 192.6 页/分 |

**结论：4 槽并发带来约 1.4–2.5× 吞吐**，代价是单页延迟上升。批量 PDF 用并发，交互单页用单槽。

## 2. 能力分级（全部为实测）

### A 级 —— 直接可用，作为 v1 主功能

| 能力 | 实测结果 | 样本 |
|---|---|---|
| 印刷中文整页 → Markdown | **100%** 字符准确率 | `para-clean/blur2/noisy/lowcontrast` |
| 双栏中文版面 + 阅读顺序 | **100%**，两栏顺序正确、无串行 | `zh-two-col`（10 行/212 字） |
| 中英混排 | **100%**，中英各自字体与行结构均正确 | `mix-en-zh` |
| 日语 | **100%**（132/132 字） | `ja-paragraph` |
| 俄语 | **100%**（266/266 字，仅 2 处多余空格，无错字） | `ru-paragraph` |
| 拉丁大写随机码（20 个 3 字母） | **100%**，逐字全对 | `nonce-table` |
| 收据整页 | **100%** | `receipt.jpg` |
| 表格 → OTSL | **100%** | `table-simple`（5×4） |
| 表格合并单元格 → OTSL | **结构正确**：横合并出 `<lcel>`，纵合并出 `<ucel>` | `table-merged`（详见 §3.1） |
| 公式 → LaTeX | math-normalized **94.8%**，15 段中 14 段完整 | `dense-equations` |
| KIE → JSON Schema | JSON 合法，**6/6 键全部正确**，日期归一化 `2017-10-18`，金额 `5.90` | `receipt` KIE |
| 退化扫描鲁棒性 | 高斯模糊 4px **97.1%**、对比度 25% **100%**、1/4 分辨率 **98.6%**、椒盐噪声 **100%** | `fixtures/degraded/*` |
| 输出确定性 | 同 prompt × 5 次，两两一致性 **100%** | — |

这是这个模型最强的地方：**0.87B 参数在消费级 GPU 上能稳定输出印刷文档的完整 Markdown/OTSL/LaTeX，且对扫描退化极其鲁棒。**

### B 级 —— 有条件可用，UI 需标注限制

| 能力 | 实测 | 限制与对策 |
|---|---|---|
| 手写公式 | plain **85.0%** / math-norm **89.0%** / 段落加权相似度 **79.9%** | 19 段中 2 段代数展开错（`(a+λ)^2` 类）。**必须整页识别**，不做区域切分 |
| 图像 token 预算的收益 | 印刷页 630 tok 得 **97.0%**、9142 tok 得 **94.8%**（无提升）<br>手写页 4000→8230 tok 得 **74.6%→85.0%**（+10.4） | 印刷文档吃低保真档；手写/大扫描才值得加预算 |
| 繁体中文 | 输出**简体**（貟外→员外、散騎→散骑、次韻→次韵），字符准确率 85.7% | 不是识别错误，是模型规范化输出。**UI 不得宣称「保留繁体原样」** |
| 竖排中文 | 内容全对，但自动**补标点**（GT 无标点 → 「白日依山尽，黄河入海流。」），字符比对 80% | 竖排可读但不保真；编辑场景需提示 |
| 长密排公式页完整性 | 15 段会丢 1 段（Eq.5 整条公式被跳过，模型直接续写后文） | 单页公式密度极高时建议整页 + 「补段」复核，或按栏切分两次跑 |

### C 级 —— 模型级缺陷，v1 不做承诺

| 能力 | 实测 |
|---|---|
| **韩语** | **失败**。字符级准确率看似 86.2%–87.0%，但**语义已崩**——错的是韵尾与字母本身：`주출`(추출 提取)、`매리금`(머리글 页眉)、`바당将`(바닥글 页脚，还混入汉字)、`마克다운`(마크다운)、`원기`(읽기)、`정화도`(정확도)、`화인`(확인)、`체스트`(테스트)。特征是**字母/韵尾混淆 + 随机插入汉字**。提高分辨率（427→1099 tok）与放大字号到 44px 均无改善 → 属训练数据缺失，非工程问题。字符准确率指标在此**严重低估损伤**，因为替换后的字仍是韩文字符 |
| 生僻字 | 随机抽取 300 常用字表外的罕见汉字，document prompt **65.8%**，text prompt **13.7%**（且触发退化） |
| 印章 / 遮挡 | 未测，据 C 级归因保守标注 |

### D 级 —— 完全不具备

| 能力 | 实测 |
|---|---|
| **字符级 bbox / 坐标** | 直接询问坐标，输出 `[{"text":"行书千文"},{"text":"梁员外散骑侍郎周兴嗣次韵"},...]`——**有 text 无任何坐标字段**。模型架构上不输出 grounding |
| 置信度分数 | 无 |

**因此「字符级原文对照高亮」不可实现**。v1 只能做**块级/段落级对照**（用自研版面检测或行投影给出包围盒，把模型输出的段落与框对齐）。这是本报告对原计划最重要的一处修正。

## 3. 结构性发现

### 3.1 OTSL 合并单元格是可靠的

输入（`table-merged`）：`季度` 纵跨 2 行、`产品线` 横跨 2 列。

模型输出：

```
<fcel>季度<fcel>产品线<lcel><fcel>营收<nl><ucel><fcel>硬件<fcel>软件<ucel><nl><fcel>Q1<fcel>52<fcel>48<fcel>100<nl>
```

- `<lcel>` 正确表示「延续左格」（横合并）
- `<ucel>` 正确表示「延续上格」（纵合并）
- 唯一差错：第 2 行末列的 `100` 被写成 `<ucel>`（把有值单元格误判为纵向延续）

**结论：OTSL → HTML 的转换器必须实现 colspan/rowspan 推导**（`<lcel>` 向右合并、`<ucel>` 向上合并、`<ecel>` 空单元格），并允许用户手工修正个别格子。这也再次确认原计划「用 HTML 而非 GFM 导出表格」是对的。

### 3.2 退化（重复输出）不是主路径风险

用多尺度连续重复 run 检测（同一 1–32-gram 连续重复 ≥4 次才算退化），对全部样本扫描：

| 样本 | 退化占比 | 说明 |
|---|---|---|
| 印刷整页 / 密集公式 / 手写 / 双栏 / 混排 / 退化扫描 | **0.0%** | 无一例循环 |
| nonce 生僻字 + `document` prompt | **0.0%** | 稳定 |
| nonce 生僻字 + `text` prompt | **55.9%** | 输出尾部 `㕥` 连续重复 **81 次**，前半段内容被吞 |

**结论**：
1. 之前用「24-gram 出现频率」算出的 11.2% / 17.7% 重复率是**假阳性**——那是公式里 `\boldsymbol{k}_{[t]}^{i^\top}` 合法重复出现 7 次。
2. 真实退化只在**分布外输入（生僻字）+ 宽松 prompt** 时出现，正常文档与退化扫描均 0%。
3. **重复抑制从 P0 降为 P1 守卫**：检测到连续重复 run 就换 prompt（`text`→`document`）重试一次，仍失败则截断并标记该页可疑。原计划把它列为 P0 强约束是过度设计。

### 3.3 prompt 选择

- 正常内容：`document` 与 `text` 两版 prompt 结果**完全等价**（退化扫描 12/12 组一致）。
- 分布外内容：`document` 显著更稳（65.8% vs 13.7%，且不退化）。
- 四种 task prompt（document / text / table / formula）都能稳定遵循，**不需要 GBNF 约束**（temperature=0 下 5 次 100% 一致）。

**默认统一用 `document` prompt**；`text` 仅在「纯文本快路径」且已知内容熟悉时使用。

### 3.4 上下文预算

| 页型 | image tokens | 输出 tokens | 合计 |
|---|---|---|---|
| dense 公式页（2.35 MP） | 2366 | 1613 | 3979 |
| dense 放大 2×（9.38 MP） | 9142 | 1603 | 10745 |
| 手写页（8.29 MP，高预算） | 8230 | 1023 | 9253 |
| 轻页 | 200–1100 | ≤200 | ≤1300 |

**`-c 16384` 对单页够用**（最坏 10745）。但：
- 批量并发 4 槽需 `-c 40960`（每槽 10240），显存 KV 约 12 KB/token × 40960 ≈ 0.5 GB，A770 的 16 GB 完全装得下。
- 上游警告 `Qwen-VL models require at minimum 1024 image tokens`——对小图（<1 MP）确实应设 `--image-min-tokens 1024`，否则细字会糊。

## 4. 对 v1 功能范围的裁决

依据以上数据，**批准 / 降级 / 砍掉**：

| 原计划功能 | 裁决 | 依据 |
|---|---|---|
| 整页 Markdown 识别 | ✅ **v1 核心** | A 级，100% |
| 表格 → HTML（OTSL 中间表示） | ✅ **v1 核心** | A 级，含 lcel/ucel |
| 公式 → LaTeX | ✅ **v1 核心** | A 级 94.8% |
| KIE → JSON Schema | ✅ **v1**（收据/发票类） | A 级，6/6 键 |
| PDF 逐页批处理 | ✅ **v1**，用 `--parallel 4` | 2× 吞吐 |
| 块级原文对照 | ✅ **v1**（替代字符级） | D 级 bbox |
| 手写识别 | ⚠️ **v1 但标黄**：整页模式 + 高预算档（4096 tok） | B 级 85–89% |
| 区域并发加速（PP-DocLayoutV3） | ⏸ **v2 可选** | 印刷页低保真已 97%，切图收益不抵复杂度；手写页反而必须整页 |
| 多语言：日/俄 | ✅ v1 标注支持 | 99–100% |
| 多语言：韩 | ❌ **v1 不支持，UI 明确标注** | C 级，模型级缺陷 |
| 竖排 | ⚠️ 可读但不保真（自动补标点） | B 级 |
| 繁体保真 | ❌ 不做承诺，输出简体 | B 级规范化行为 |
| 字符级高亮 | ❌ **删除** | D 级 |
| 重复抑制 | 🔽 P0 → **P1 守卫**（检测 + 换 prompt 重试） | §3.2，正常输入 0% |
| 置信度显示 | ❌ 无此能力 | 模型不输出 |

### 默认运行参数（写入 `packages/inference`）

```
--parallel 4
-c 40960                 # 每槽 10240
--image-min-tokens 1024   # 小图别糊
--image-max-tokens 2560   # 默认档 ≈ 2.7 MP，prefill ≈ 2.5 s
-ngl 99 -dev Vulkan0
```

三档画质预设（对应 §1.2 成本表）：

| 预设 | image-max-tokens | prefill | 单页总时 | 用途 |
|---|---|---|---|---|
| 快速 | 1280 | ~0.8 s | ~2 s | 批量扫描件、纯文本 |
| 标准（默认） | 2560 | ~2.5 s | ~6 s | 印刷文档、报告 |
| 高保真 | 5120 | ~8 s | ~15 s | 手写、公式密集、小字号 |

超过 5120 需用户手动确认（prefill 会跳到 27 s 量级，交互不可接受）。

## 5. 待补测（不阻塞 M1）

1. **印章 / 表格压字 / 手写批注叠加**：C 级归因尚无实测。
2. **多页 PDF 跨页表格续接**：需真实教材样本。
3. **BF16 全权重 vs Q4_K_M 的精度差**：本轮未做（A770 16 GB 装得下 BF16 1.77 GB）。若 M1 发现某类文档掉点，再补这组对照。
4. **`-np 4` 下的显存峰值**：仅测了单槽 4.16 GB。
5. **中文常用字真实长文**（非 arXiv 论文）的整页准确率：需要非公开语料，避免训练集泄漏。

## 6. 复现方式

```bash
# 1) 资产（已落盘）
bash scripts/m0-fetch.sh                       # llama.cpp b12110 + Q4_K_M + mmproj + 官方 fixtures
python scripts/m0-make-fixtures.py             # 多语言/竖排/表格/公式
python scripts/m0-make-fixtures2.py            # 合并单元格/双栏/混排/大字号韩语
python scripts/m0-make-nonce.py                # 随机汉字 / 随机字母码（防先验作弊）
python scripts/m0-make-degraded.py             # 模糊/低对比/低分辨率/噪声
python scripts/m0-make-scale.py                # dense 页 0.5×–2× 缩放（成本模型）

# 2) 起服务
bash scripts/m0-server.sh 8090                 # 默认档
bash scripts/m0-server.sh 8092 --image-min-tokens 256 --image-max-tokens 16384 -c 32768   # 高预算
bash scripts/m0-server.sh 8093 --parallel 4 -c 32768 --image-max-tokens 4096 --image-min-tokens 1024  # 并发

# 3) 测量
node scripts/m0-bench.mjs                      # 13 例主基准
node scripts/m0-batch2.mjs                     # 合并单元格/双栏/混排/大字号韩语
node scripts/m0-nonce.mjs                      # 先验无关的真视感知准确率
node scripts/m0-degraded.mjs                   # 退化扫描鲁棒性 + 退化率
node scripts/m0-cost.mjs                       # prefill 成本模型
node scripts/m0-acc-sweep.mjs                  # 准确率 vs token 预算
node scripts/m0-throughput2.mjs                # 串行 vs 并发吞吐
node scripts/m0-analyze.mjs                    # 数学归一化准确率 + 块级覆盖率
node scripts/m0-degen.mjs docs/*.txt           # 多尺度连续重复 run 检测
```

原始数据：`docs/capability-raw.json`、`docs/capability-analyzed.json`、`docs/cost-model.json`、`docs/accuracy-vs-tokens.json`、`docs/degraded-results.json`。
